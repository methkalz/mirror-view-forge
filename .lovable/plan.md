

# إصلاح مشاكل الطائرات: الانتقال بين الموجات + سلوك القصف والتتبع

## المشاكل المكتشفة

### 1. الطائرات تمنع الانتقال للموجة التالية
في مرحلة `clearing` (سطر 1350)، الكود ينتظر حتى `activeDrones === 0` قبل الانتقال. الطائرات التي أُعطيت سرعة خروج في سطر 1308-1314 تُزال فقط إذا خرجت من الشاشة (سطر 1343). لكن إذا كانت الطائرة بطيئة أو عالقة، تبقى إلى الأبد.

**الحل**: إضافة مؤقت أقصى (5 ثوان) لمرحلة `clearing` — بعده يتم إزالة جميع الطائرات المتبقية قسرياً.

### 2. طائرة القنابل (Bomber) تلقي القنابل للأعلى
السطر 2414: `bomb.pos = { x: d.pos.x, y: d.pos.y + d.size }` — صحيح نظرياً (أسفل الطائرة). لكن المشكلة الحقيقية أن القنبلة نوعها `cluster` وتستخدم منطق القوس الباليستي بدل السقوط المباشر. القنابل تتحرك بمسار قوسي يبدأ بحركة لأعلى.

**الحل**: تغيير منطق قنابل الـ bomber لتكون سقوط مباشر للأسفل (نوع `shrapnel` بسيط أو `falling = true` مع `vel.y > 0` بدون مسار باليستي). تعيين `clusterPhase = undefined` و `isClusterBomb = false` لمنع منطق التشظي.

### 3. طائرة التتبع (Tracker) لا تهاجم فعلياً
السطر 2311-2328: الـ tracker تغوص نحو اللاعب لكن **لا تسبب ضرراً أثناء الغوص**. الاصطدام (collision) في سطر 2431 يستثني الـ bomber فقط (`d.tier !== 'bomber'`) لكن يتطلب أن تقترب لمسافة `d.size + p.size`. المشكلة أن السطر 2324 يعكس اتجاهها قبل أن تصل للاعب (`d.pos.y > p.pos.y - 10`)، فترتد قبل الاصطدام.

**الحل**: 
- جعل الـ tracker تُطلق "رصاصة طاقة" أو قذيفة خفيفة عند الغوص بدل محاولة الاصطدام المباشر
- أو تعديل شرط الارتداد ليكون بعد مرورها بمستوى اللاعب فعلياً

### 4. الطائرات تنزل قريباً جداً من اللاعب
السطر 2359: `targetY = p.pos.y - 30` للـ scout — قريب جداً! والـ bomber: `p.pos.y - 80`.
السطر 2353-2354: `maxY = g.height * 0.58` — يمكن أن تصل الطائرة لـ 58% من الشاشة.

**الحل**: رفع الحد الأدنى للارتفاع:
- Scout: `targetY = p.pos.y - 120` (بدل -30)
- Bomber: `targetY = p.pos.y - 150` (بدل -80)
- Tracker orbit: رفع مركز المدار
- `maxY = g.height * 0.42` (بدل 0.58)
